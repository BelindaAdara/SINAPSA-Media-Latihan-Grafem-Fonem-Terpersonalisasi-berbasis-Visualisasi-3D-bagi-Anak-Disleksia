- Konteks: nama pengembang belum diberikan; pilihan: pertahankan placeholder `[ISI NAMA PENGEMBANG]`; alasan: SRS menugaskan pengisian nama melalui konfigurasi aplikasi dan tidak ada nama yang dapat dipastikan.
- Konteks: fase 1 belum membangun mekanik latihan mobile; pilihan: aktifkan hanya `listen_choose` dan `discriminate`, jenis lain seed sebagai nonaktif; alasan: mengikuti aturan SRS bahwa jenis yang belum diimplementasikan harus terkunci.
- Konteks: repo awal kosong dan backend Fase 1 perlu diuji tanpa kredensial Supabase; pilihan: injeksikan repository ke Express app dan gunakan repository tiruan di tes; alasan: menjaga batas data dan menguji API secara deterministik.
- Konteks: POST sesi memperbarui sesi, item, dan mastery; pilihan: hitung delta dengan fungsi murni di backend lalu tulis ketiganya melalui satu RPC PostgreSQL transaksional; alasan: kegagalan atau percobaan ulang tidak meninggalkan sesi tanpa item/mastery.
- Konteks: data seed strokes harus mudah diperbarui tanpa merusak transformasi b/d/p/q; pilihan: jadikan `generate-strokes.js` sumber pembangkit `seed.sql`; alasan: geometri turunan selalu dihasilkan dari geometri `b` yang sama.
- Konteks: Supabase key tidak tersedia di lingkungan pengembangan; pilihan: konfigurasi server memerlukan kredensial hanya ketika default repository digunakan; alasan: tes endpoint dapat berjalan tanpa rahasia maupun koneksi eksternal.
- Konteks: kolom `age` di SRS mengizinkan null di database tetapi onboarding mengharuskan usia; pilihan: API membuat profil selalu memerlukan usia; alasan: mengikuti persyaratan onboarding.
- Konteks: SRS membolehkan goresan huruf selain b disederhanakan; pilihan: gunakan garis prosedural 1–3 goresan dan turunkan d/p/q persis dari b; alasan: memenuhi seluruh alphabet tanpa aset eksternal.
- Konteks: NFR-6 meminta pemeriksaan ESLint dasar; pilihan: tambahkan ESLint dengan aturan inti tanpa plugin; alasan: memenuhi kualitas minimum dengan dependensi dan konfigurasi yang ringkas.
- Konteks: SRS menetapkan React Navigation, sedangkan petunjuk scaffold Expo menyarankan Expo Router; pilihan: gunakan React Navigation dengan bottom tabs dan nested stack; alasan: SRS adalah spesifikasi aplikasi dan merupakan sumber kebenaran.
- Konteks: mobile memerlukan API saat dijalankan pada ponsel; pilihan: `EXPO_PUBLIC_API_URL` lokal menunjuk IP LAN `192.168.18.52`, bukan `localhost`; alasan: `localhost` pada ponsel merujuk ke ponsel itu sendiri. Ubah bila IP komputer berubah.
- Konteks: lima mekanik latihan sudah diimplementasikan; pilihan: kelima jenis ditandai aktif pada generator dan seed; alasan: sesuai permintaan agar semua prioritas tersedia. Database Supabase aktual belum diselaraskan karena backend `.env` tidak ada; jalankan ulang seed di Supabase.
- Konteks: aplikasi dilarang memakai media eksternal; pilihan: bentuk 3D dibuat dari geometri goresan dan menggunakan fallback 2D; ilustrasi/avatar dan aksen UI berbasis bentuk SVG/teks.
- Konteks: build bundle Metro awal gagal karena `babel-preset-expo` tidak tercantum sebagai dependency; pilihan: tambahkan preset ke devDependencies; alasan: konfigurasi Babel Expo membutuhkannya secara eksplisit.
- Konteks: Expo SDK 58 memberi lint default yang memicu false positives untuk mutasi frame Three.js dan gestur PanResponder; pilihan: pakai ESLint Expo langsung dan nonaktifkan aturan tersebut hanya pada viewer 3D; alasan: mutasi itu diperlukan untuk interaksi 3D imperative dan bukan state React yang dirender.
- Konteks: pengujian endpoint real meminta kredensial backend yang tidak tersedia; pilihan: tandai integrasi Supabase belum diuji dan tidak menjalankan request mutasi; alasan: tidak menggunakan kredensial tiruan dan tidak mengklaim hasil eksternal yang belum terverifikasi.
- Konteks: `npm audit` pada dependency mobile menunjukkan tiga kerentanan moderat transitif; pilihan: tidak menjalankan `audit fix --force`; alasan: perbaikan paksa yang ditawarkan dapat menurunkan versi Expo utama dan mengubah dependency native di luar scope tanpa evaluasi kompatibilitas.
- Konteks: generator sebelumnya menonaktifkan tiga mekanik latihan yang saat ini sudah tersedia; pilihan: aktifkan kelima jenis dalam generator dan hasil `seed.sql`; alasan: memenuhi ruang lingkup akhir SRS. Database Supabase yang sudah ada perlu menerima ulang seed.
- Konteks: sesi latihan memakai mekanik berbeda tetapi menyimpan format item hasil yang sama; pilihan: rekam jawaban pertama, jumlah percobaan, penggunaan petunjuk, resolusi, dan waktu respons untuk seluruh jenis; alasan: menjaga konsistensi endpoint sesi dan perhitungan mastery.
- Konteks: tracing menggunakan SVG dengan rasio aspek tetap; pilihan: hitung ulang titik sentuh setelah memperhitungkan skala dan padding tampilan; alasan: koordinat sentuh harus sejajar dengan goresan huruf di layar.
- Konteks: paket Expo scaffold menyertakan PNG contoh yang tidak dipakai; pilihan: hapus ikon/splash bawaan; alasan: menjaga repositori bebas aset gambar yang tidak diperlukan.
- Konteks: environment untuk tes integrasi tidak ada; pilihan: laporkan `GET /letters`, `POST /children`, `POST /sessions`, `GET /dashboard/:childId`, `GET /progress/:childId`, `GET /recommendations/:childId`, `PUT /sessions/:id`, dan `DELETE /sessions/:id` sebagai belum diuji; alasan: tidak mengganti kredensial atau memanggil layanan/data proyek pengguna tanpa konfigurasi yang tersedia.
- Konteks: pengguna kemudian menjalankan uji integrasi nyata dari `backend/requests.http`; hasil yang dilaporkan: `GET /health`, `GET /letters` (26 huruf), `GET /exercise-types` (5 aktif), `GET /dashboard/:childId`, `GET /progress/:childId`, `GET /recommendations/:childId`, `PUT /sessions/:id`, dan `DELETE /sessions/:id` berhasil dengan 200; `POST /children` dan `POST /sessions` berhasil dengan 201 Created, sesuai semantik HTTP. Pembuatan sesi menghasilkan skor 50, 2 item, durasi 390 detik, dan mastery b: 0→10 serta d: 0→4. Respons teramati pengguna, bukan pengujian ulang otomatis dari sesi ini.
